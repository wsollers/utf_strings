# GitHub Copilot Instructions

## Project Context
This is the UTF Strings library - a high-performance C++23 library for UTF-8/16/32 string processing.

### Code Generation Guidelines

### Language & Standards
- Use **C++23** features and modern idioms exclusively
- Write idiomatic modern C++23 - avoid legacy C++ patterns
- Compile with GCC 13+, Clang 18+, or MSVC 2022+
- Follow project's snake_case naming for functions/variables
- Use PascalCase for types and classes
- All code in `utf` namespace

### CRITICAL: Testing Requirements
- **Every new function MUST have unit tests** - no exceptions
- **All tests MUST pass** before code is complete
- Use Google Test framework following existing patterns
- Cover normal cases, edge cases, and error conditions
- Include performance regression tests for critical functions

### Code Style
```cpp
// Function naming
auto convert_utf8_to_utf16(std::string_view input) -> std::u16string;

// Type naming  
class UtfConverter;
struct EncodingTraits;

// Constants
constexpr size_t max_utf8_sequence_length = 4;
```

### Modern C++23 Patterns to Follow
1. **Input validation with modern error handling**:
```cpp
auto process_utf8(std::u8string_view input) -> std::expected<result_type, error_code> {
    if (input.empty()) return std::unexpected(error_code::empty_input);
    if (!is_valid_utf8(input)) return std::unexpected(error_code::invalid_utf8);
    // ... process
}
```

2. **Use concepts for template constraints**:
```cpp
template<utf_encoding T>
requires std::same_as<T, char8_t> || std::same_as<T, char16_t>
auto convert_encoding(std::basic_string_view<T> input) -> std::string;
```

3. **Structured bindings for multiple returns**:
```cpp
auto [result, error] = try_convert_utf8_to_utf16(input);
if (error) { /* handle error */ }
```

4. **Constexpr and consteval for compile-time operations**:
```cpp
consteval auto max_utf8_sequence_length() -> size_t { return 4; }
constexpr auto is_ascii(char8_t c) -> bool { return c < 0x80; }
```

5. **Always include corresponding unit tests**:
```cpp
// For every function you generate, also provide:
TEST(Utf8ConversionTest, HandlesValidSequences) {
    auto result = convert_utf8_to_utf16(u8"Hello, 世界!");
    ASSERT_TRUE(result.has_value());
    EXPECT_EQ(result.value(), u"Hello, 世界!");
}
```

### Testing Patterns
- Create comprehensive test cases for edge cases
- Test with invalid UTF sequences  
- Include performance regression tests
- Add fuzz targets for new parsing code

### Performance Considerations
- Prefer algorithms that can be vectorized
- Consider memory alignment for UTF-32
- Use lookup tables for classification when beneficial
- Profile hot paths with benchmarks

### Error Handling
- Use exceptions for programming errors
- Return optional/expected for data errors
- Provide both throwing and non-throwing variants when appropriate

### Documentation
- Use Doxygen-style comments for public APIs
- Include complexity information for algorithms
- Document encoding assumptions and requirements
- Provide usage examples for complex functions
