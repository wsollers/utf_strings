# GitHub Copilot Instructions

## Project Context
This is the UTF Strings library - a high-performance C++23 library for UTF-8/16/32 string processing.

## Code Generation Guidelines

### Language & Standards
- Use **C++23** features and modern idioms
- Compile with GCC 13+, Clang 18+, or MSVC 2022+
- Follow project's snake_case naming for functions/variables
- Use PascalCase for types and classes
- All code in `utf` namespace

### Code Style
```cpp
// Function naming
auto convert_utf8_to_utf16(std::string_view input) -> std::u16string;

// Type naming  
class UtfConverter;
struct EncodingTraits;

// Constants
constexpr size_t max_utf8_sequence_length = 4;
```

### Common Patterns to Follow
1. **Input validation first**:
```cpp
if (input.empty()) return {};
if (!is_valid_utf8(input)) throw std::invalid_argument("Invalid UTF-8");
```

2. **Use string_view for inputs**:
```cpp
auto process_utf8(std::u8string_view input) -> result_type;
```

3. **Return optional/expected for fallible operations**:
```cpp
auto try_convert(std::string_view input) -> std::optional<std::u16string>;
```

4. **Template for endianness when relevant**:
```cpp
template<endian E = endian::native>
auto convert_utf32(std::u32string_view input) -> std::string;
```

### Testing Patterns
- Create comprehensive test cases for edge cases
- Test with invalid UTF sequences  
- Include performance regression tests
- Add fuzz targets for new parsing code

### Performance Considerations
- Prefer algorithms that can be vectorized
- Consider memory alignment for UTF-32
- Use lookup tables for classification when beneficial
- Profile hot paths with benchmarks

### Error Handling
- Use exceptions for programming errors
- Return optional/expected for data errors
- Provide both throwing and non-throwing variants when appropriate

### Documentation
- Use Doxygen-style comments for public APIs
- Include complexity information for algorithms
- Document encoding assumptions and requirements
- Provide usage examples for complex functions

## Build Integration
When suggesting build changes:
- Update `CMakeLists.txt` for new source files
- Consider Conan dependencies in `conanfile.py`
- Add appropriate compiler flags for new features
- Update CI workflows if needed

## Current Focus Areas
- UTF validation algorithms
- Conversion between UTF-8/16/32
- Performance optimization
- Cross-platform compatibility
- Security hardening
